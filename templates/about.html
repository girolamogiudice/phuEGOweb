phuEGOweb

Web interface for running phuEGO, exploring propagated networks, and interpreting enrichment-driven modules.

What phuEGOweb Does

phuEGOweb runs a network propagation workflow from submitted proteins or genes, separates increased and decreased signals, decomposes the propagated signal into seed-centred ego networks, merges related egos into modules, and reports network, table, enrichment, and cross-experiment outputs.

Enrichment uses the annotation files bundled with the selected network under support_data/support_data_<network>/genesets. In manifests this is reported as "fisher_background": "Network", because the effective Fisher background is the selected network's annotated nodes.

Submission Forms

Phospho phuEGO

Use this for phosphoproteomics-style inputs where each row is a phosphoprotein or protein identifier and a signed log-fold change. 

>EGF_vs_Untreated
P00533  2.48
Q8TD19  2.00
P29317 -0.91
P10398 -0.86

Single Cell phuEGO

Use this for gene or UniProt log-fold-change lists. Gene names are converted to UniProt when present in the mapping file. 

>Cluster_1_vs_rest
EGFR   1.80
JUN    1.25
MAPK1 -0.70
STAT3 -1.10

Custom phuEGO

Use this when you want to provide a layer for each seed. Each data row must contain identifier, LFC, and layer. Layers must be 1, 2, or 3. 

>Experiment_A
P00533  2.48  1
Q8TD19  2.00  2
P29317 -0.91  1
P10398 -0.86  3
Input rules. Start each experiment with >experiment_name. Use tabs or spaces between columns. Positive LFC values are analysed as increased seeds; negative values are analysed as decreased seeds. Multi-experiment submissions create one result view per experiment plus cross-experiment summaries when available.

Parameter Meaning

Field Meaning
Network Reference network and matching support-data folder. This also determines the Fisher enrichment background.
First Propagation Damping Random-walk-with-restart damping for the first propagation from submitted seeds. Reanalysis keeps this fixed so existing RWR and p-values can be reused.
First Propagation Significance P-value threshold applied to propagated RWR scores before ego decomposition.
KDE Probability Cutoff used to retain seed-centred ego networks. Optimal searches cutoffs automatically; numeric values use the selected fixed cutoff.
Zscore Semantic Similarity Semantic-similarity z-score threshold used when filtering ego nodes for functional coherence.
Second Propagation Damping Damping used during ego decomposition.
Minimum Ego Nodes Minimum size required for a seed-centred ego network to be retained.
Third Propagation Damping Damping used during module detection and ego merging.
Fisher Significance P-value threshold for enrichment outputs.

Retrieve and Reanalysis

The Retrieve page accepts a previous UUID. It opens a summary page where you can view the existing results unchanged or launch a reanalysis.

Reanalysis creates a new UUID. The original run is kept intact. Input, network, and first propagation damping are fixed; existing rwr_scores.txt and pvalues.txt are copied and reused when present. You can change the downstream thresholds and module/enrichment parameters.

How to Interpret Results

Top Summary

The dashboard is a compact run summary. Values are split into increased and decreased directions, matching positive and negative LFC seeds.

Statistic How to read it
Seeds Submitted proteins or genes after parsing the input, separated by sign of LFC.
In graph Submitted seeds that are present in the selected input network. Missing seeds cannot be propagated.
RWR Network nodes passing the random-walk-with-restart significance threshold.
Overlap Nodes that pass the RWR threshold in both increased and decreased directions before unique-direction filtering.
Supernodes Retained seed-centred ego structures after KDE filtering. These are the main local network units.
Nodes / Edges Total nodes and connections in the final supernode network for each direction.
Low degree Seeds that were present in the input network but did not form a retained supernode, usually because their local ego network was too small, too weakly connected, or did not pass the KDE/semantic filtering steps.
Modules Number of detected clusters after merging related supernodes.
In modules Supernode-network nodes assigned to modules after clustering; isolated or unassigned nodes are excluded.

The Submitted Seed Coverage table lists the actual gene/protein names for seeds missing from the input network and seeds not retained in the supernode graph. This is the best place to check whether unexpected missing biology is caused by identifier mapping, network coverage, or filtering.

Increased and Decreased Tabs

Each direction has its own supernode network, enrichment tables, module network, module-specific tables, and heatmaps. Increased corresponds to positive LFC seeds; decreased corresponds to negative LFC seeds.

The two directions should be interpreted independently first. A strong increased module and a strong decreased module may involve different parts of the network, or they may share propagated nodes before the unique-direction step. The overlap statistic helps diagnose how much the two directions compete for the same network region.

Supernodes and Modules

Supernodes are collapsed seed-centred ego structures. Modules are groups of related supernodes after merging and clustering. Click a module in the legend to highlight its nodes; Shift-click isolates that module. Use Restore network to return to the full view.

In the supernode network, purple nodes represent collapsed supernodes. Expanding a supernode reveals the genes/proteins inside its local neighbourhood. The module network is a stricter module-level view: choosing a module from the selector loads that subnetwork and its matching enrichment tables.

Highlighting and Subgraphs

The results page supports two related interactions. A normal click highlights a matching gene set while keeping the full network visible. Shift-click extracts or isolates the selected set so the rest of the graph is hidden. This works from module legends and from enrichment rows. To restore the full network, use the Restore network button above the enrichment table or the reset/restore controls in the network area.

Use highlighting when you want context, and use Shift-click isolation when the network is dense and you want to inspect only the genes supporting a module, term, or pathway.

Data Tables

The Supernodes Data and Module Data sections contain several tabs. Enrichment shows over-represented annotations for the selected supernode set or module. Drugs, Diseases, and Druggability report external annotations when those files are available. Module tables are specific to the currently selected module, while supernode tables summarize the full direction-level supernode network.

In enrichment tables, the ID is the pathway or ontology term, the description is the readable term name, the p-value is the Fisher enrichment score, and the gene column lists the network genes driving the enrichment. The View all control expands long gene lists.

Enrichment Tables and Figures

Enrichment databases are reported with short codes: C cellular component, F molecular function, P biological process, K KEGG, RT Reactome, and R pathway/resource annotations. Click an enrichment row to highlight its genes in the network; Shift-click isolates that gene set. Summary figures can be downloaded as image/vector outputs.

The Summary figures card visualizes the active enrichment table. Bar and dot plots emphasize the strongest terms, heatmaps show term/gene structure, circle and sankey-style plots help inspect relationships between terms and genes, and module heatmaps connect GO terms to modules when module-level data are available. Use the Top N selector to reduce crowded plots; use the text-size control and download menu when preparing figures.

The Enrichment Heatmap / GO-term modules card summarizes how enriched GO terms distribute across modules. It is useful for seeing whether a biological process is concentrated in one module or shared across several modules. The heatmap supports pan/scan behaviour for large labels and can be downloaded.

Cross-Experiment View

When a submission contains multiple experiments, the cross-experiment tab compares results across experiments for the same propagation setting. It is designed to answer whether experiments recover similar network structures, whether modules recur across conditions, and whether increased or decreased signals show consistent patterns.

The cross-experiment KDE view compares direction-level propagated signatures. The module similarity network connects modules or experiments that share similar module composition. The matrix/heatmap view makes repeated module relationships easier to scan across all experiments. Use this tab after inspecting individual experiments, not before: it is most informative once you know what the main modules mean biologically.

Downloads

Network JSON, GraphML, TXT tables, enrichment files, plots, and module-specific files are available from the relevant buttons in each section. Downloaded enrichment files correspond to the same network-specific background used during the analysis.
